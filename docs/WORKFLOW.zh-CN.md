# 截图到长期知识库：首版设计与试用

## 产品决定

以现有 Obsidian 桌面插件为处理核心，以 iPhone 明确选图并保存到同步 Inbox 为轻量入口。不开发独立 App，不扫描全相册，不按 X、LinkedIn、笔记、YouTube 或 Bilibili 分文件夹。主要组织轴是内容含义，论文、AI 新闻、工具/skills 只是可以自行选择的初始主题，不限制其他内容。

上游：https://github.com/travisvn/obsidian-vision-recall

Fork：https://github.com/liranmao/obsidian-vision-recall

本地开发分支：`feat/topic-digests`。本轮修改只交付本地，没有推送、发布或上游 PR。

## 工作流

1. **明确选入**：在手机照片中选中值得保留的截图，分享/存储到可同步的 vault `VisionRecall/Intake`。不选择的照片不接触。
2. **同步和入箱**：图片到达桌面 vault 后，通过命令「处理已选入 Inbox 的截图」处理。也可在原有配置里启用自动/周期入箱处理，默认保持关闭。
3. **提取知识条目**：复用 OCR → 视觉分析 → 摘要 → 标题/标签 → Markdown 笔记与 JSON 元数据。原图复制到 Screenshots，知识笔记始终保留原图链接。输入里的指令作为截图数据，不作为执行指令。
4. **去重**：已有 SHA-256 图片哈希去重；本版额外检查长期条目哈希，避免上游 30 天短期缓存清理后重新处理旧图。相同二进制图片改名仍可识别；裁剪、压缩、同文不同图的语义去重尚未实现。
5. **主题归类**：在设置中先写自己的主题与关键词/别名。匹配标题、OCR、已有 AI 摘要和标签，支持跨主题。未匹配进入「待分类」。这是可解释的关键词归类，不是额外的语义分类模型。
6. **主题演化**：从已有 AI 标签生成候选，按去重截图出现次数排序，显示最多 20 条。点击「接受」才加入主题；「忽略」持久保存，可恢复。接受后按新主题重新生成历史汇总；主题重命名/删除通过编辑列表实现。没有自动合并/自动采纳。
7. **每日汇总**：复用已有摘要，按主题聚合，并列出共同标签线索、每条摘录、原笔记和原图。首版是摘录式综合，不额外调用模型进行跨材料推理，也不会把多张截图的说法写成已证实结论。
8. **关联旧笔记**：只按已有笔记标题中的主题关键词选最多 5 个链接，明确标记为待复核关联。不修改旧笔记，不进行全库 embedding 检索。
9. **人工消化**：打开原图核对，阅读原论文/文章后再补充自己的判断。在每日文件「我的思考」中写记录；生成区是可重建数据，手写内容放在标记之外。

## 证据边界

截图只是一部分上下文。提示词要求模型区分可见事实、截图作者的主张与推断，标记缺失/不确定信息，禁止补编论文结论、统计数据、作者或 URL。不默认抓取链接，不读取完整视频，不把截图发布时间当作论文发布日期。提示词不能保证模型绝不出错，输出始终标记为未经核实的 AI 摘要。

新生成的知识笔记即使关闭「Include metadata in note」，仍会保留原图引用。历史摘要原样复用，新提示词不会自动修复旧内容。

## 手机与后台能力的真实边界

`manifest.json` 仍为 `isDesktopOnly: true`；代码包含桌面 OCR/worker 依赖。本轮没有声称插件可在 iOS 运行。

轻量入口不是已打包的 iOS 快捷指令：可在“快捷指令”手工建立「接收分享的图像 → 转为 PNG（需要时）→ 用时间戳和随机后缀命名 → 存储文件（询问保存位置）」流程，目标必须是能到达同一桌面 vault 的 Intake 文件夹。先用一张无敏感信息的测试图核实传输和文件名不覆盖。此流程尚未在真实 iPhone 上验证。

- 使用 iCloud 文件夹承载 vault 时，可通过“存储到文件”选择相应 Inbox，等待桌面下载完成。
- 使用 Obsidian Sync 时，不要假定 iOS“文件”App 一定能直接写到 vault；如果目标不可见，先将选图传到桌面，再手动放入 Inbox。也可另行实现手机 Obsidian 导入入口，但这不在本版交付中。
- 不要让两个同步工具同时同步同一 vault。只有桌面机器运行处理插件；同步服务负责文件传输，不负责运行 AI。
- 桌面 Obsidian 关闭、插件停用或机器休眠时，OCR、入箱轮询和每日汇总均不会运行。重新打开后，手动处理 Inbox，或启用原有周期处理以补处理；自动汇总开关则会在启动和每分钟补齐已有处理记录。
- 每日日期按**处理 timestamp 的本机时区**归档，不是截图拍摄日期。跨时区使用会改变日期分桶，首版尚无固定时区设置。

## 安装与试用（请使用测试 vault）

1. 本地运行 `npm ci`、`npm test`、`npm run build`。
2. 在测试 vault 建立 `.obsidian/plugins/vision-recall/`，复制根目录的 `main.js`、`manifest.json`、`styles.css`。这是本地手工安装，不会修改已有真实 vault。
3. 在 Obsidian 启用插件，配置上游已有的模型端点。云模型会接收截图/OCR等内容；如选择本机 Ollama，需自行准备可用的视觉和文本模型。API key 使用现有插件存储方式，不是系统钥匙串。
4. 打开 Vision Recall 主视图，使用原有初始化文件夹按钮创建 Intake/Screenshots/Notes/Temp。
5. 在新增「知识主题与每日汇总」设置里输入，例如：

   ```text
   论文 | paper,research,论文,研究
   AI 新闻 | AI news,发布,release
   工具与 Skills | tool,skills,工具,agent
   ```

   主题默认留空，以上仅是可编辑示例。关键词越笼统越容易误匹配。
6. 放一张 PNG/JPEG 到 `VisionRecall/Intake/`，运行「Vision Recall: 处理已选入 Inbox 的截图」。原有处理队列和图库可查看进度。
7. 运行「Vision Recall: 生成 / 更新每日主题汇总」，结果默认在 `VisionRecall/Daily/YYYY-MM-DD.md`。汇总文件夹为相对 vault 根目录的完整路径，不受原有父文件夹/前缀设置影响。
8. 在设置页刷新主题建议，接受或忽略，再生成汇总。检查原图/笔记链接、日期和内容。
9. 在「我的思考」写一句话，重复运行两次：应只保留一份每日文件、同样的条目，不改变手写内容。关闭插件重新打开，再运行以检查持久化。
10. 验证后可开启「自动更新每日汇总」。这只整理已处理内容；自动入箱由上游配置单独控制。

## 已实现与后续

已实现：用户主题、别名匹配、多主题归类、AI 标签候选接受/忽略、每日摘录聚合、原图与笔记溯源、标题关键词旧笔记关联、历史摘要兼容、汇总幂等更新、手写区保留、同名非生成笔记保护、长期哈希补充检查、Inbox 边界修正、快速多图 create 事件不再被全局 debounce 丢弃、轮询卸载清理、设置保存时 Set 序列化修正。

暂未实现：iOS 原生插件/安装包或签名快捷指令、全天候后台服务、视觉/语义近重复合并、自动可信度验证、论文全文或视频抓取、跨材料 AI 综合推理、固定时区归档、语义关联与人工逐条改分类 UI。单条数据仍沿用上游存储格式。

## 验证与限制

核心测试使用合成数据，不访问用户 vault 或真实 API。构建验证类型与打包；尚需真实 Obsidian 桌面和 iPhone 联调。自动汇总每次读取全部处理记录，适用于首版规模；大库需后续增量索引。运行期并发通过同一插件实例的共享 Promise 合并，不提供多设备分布式锁。

上游锁文件安装报告 23 项依赖漏洞（1 low、7 moderate、15 high）；本次未做可能破坏兼容性的依赖升级，也未宣称安全审计完成。
